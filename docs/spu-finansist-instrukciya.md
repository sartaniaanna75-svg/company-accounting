# Инструкция финансиста по работе с СПУ WorkTime

Документ для ежедневной работы: куда зайти, что нажать, что заполнить и где проверить результат.  
Технические настройки сервера и прав здесь не рассматриваются.

**Отчётная неделя СПУ** по умолчанию — с **четверга по среду** (например, 12–18 ноября). В интерфейсе это может быть подписано как «Четверг–среда».

---

## 1. С чего начать (краткая карта)

Рекомендуемый порядок первой настройки:

1. **Структура СПУ** — создать департаменты и поддепартаменты.  
2. **Показатели СПУ** (вкладка внутри «Структура СПУ») — создать показатели и разместить их в структуре.  
3. В карточке показателя — выбрать тип, источники или формулу, включить «Показывать в План–факте».  
4. **Настройка показателей → Планы СПУ** — задать планы на управленческий период.  
5. **Ввод показателей** — заполнить ручные факты (если есть).  
6. **План–факт компании** — проверить план, факт и выполнение за две недели.

Зависимость: без департамента нельзя корректно «посадить» показатель; без галочки «Показывать в План–факте» показатель не появится в отчёте; без источника или ручного ввода факт будет пустым.

---

## 2. Где находится СПУ в меню

В левом меню откройте блок **СПУ**. Основные разделы:

| Раздел меню | Зачем нужен |
|---|---|
| **Структура СПУ** | Дерево департаментов и вкладка **«Показатели СПУ»** |
| **Настройка показателей** | Классификация показателей, вкладка **«Планы СПУ»**, начало отчётной недели |
| **Ввод показателей** | Ручной ввод фактов по департаментам за выбранную неделю |
| **План–факт компании** | Недельный отчёт: план, факт, %, сравнение двух недель |

Важно: отдельного пункта меню «Показатели СПУ» нет. Показатели создают и настраивают внутри **«Структура СПУ»**, на вкладке **«Показатели СПУ»**.

---

## 3. Структура СПУ: департаменты

### 3.1. Открыть раздел

1. Меню **СПУ** → **Структура СПУ**.  
2. Вверху конструктора откройте вкладку **«Департаменты»** (если открыта другая).

На экране — дерево. Корень называется **«Компания»**.

### 3.2. Создать департамент

1. Нажмите **«+ Добавить департамент»**.  
2. Заполните форму:

| Поле | Обязательность | Что указать |
|---|---|---|
| **Название** | обязательно | Например: «Территория», «Магазин» |
| **Родительский департамент** | по желанию | «Компания» или другой департамент |
| **Ответственный** | по желанию | Сотрудник, ответственный за узел |
| **Статус** | рекомендуется | «Активен» или «Неактивен» |
| **Порядок отображения** | по желанию | Число для сортировки |
| **Считать итог из поддепартаментов** | по желанию | Галочка, если узел должен суммировать «детей» |

3. Нажмите **«Сохранить»**.

Результат: департамент появляется в дереве под выбранным родителем.

### 3.3. Создать поддепартамент

1. В дереве у нужного департамента нажмите **«+ Поддепартамент»**.  
2. Заполните **Название** и остальные поля.  
3. **Сохранить**.

Либо создайте обычный департамент и в поле **«Родительский департамент»** выберите нужный узел.

### 3.4. Изменить порядок и отредактировать

- Кнопки **↑** / **↓** у узла — сдвинуть среди соседних.  
- **«Редактировать»** — изменить название, родителя, статус, ответственного.  
- **«Удалить»** — программа спросит подтверждение. Если узел уже используется, предложит **перенести связи** в другой департамент или **«Сделать неактивным»**.

Неактивный узел помечается как «неактивен» и обычно не мешает истории показателей.

### 3.5. Добавить показатель прямо из дерева

У департамента есть кнопка **«+ Показатель»** — открывается карточка нового показателя с уже выбранным основным департаментом.

---

## 4. Показатели СПУ: создание и размещение

### 4.1. Открыть список показателей

1. **Структура СПУ**.  
2. Вкладка **«Показатели СПУ»**.

Доступны:

- **«+ Добавить показатель СПУ»**  
- вкладки: **Все показатели СПУ**, **Ручной ввод**, **Из Work Time**, **Расчётные**, **Из 1С**, **Архив**  
- поиск по названию и фильтр **«Департамент»**  
- в карточке: **«Настроить»**, **«Источники»**, **«Архивировать»** / **«Восстановить»**, **«Удалить»**

### 4.2. Создать показатель — обязательные поля

1. Нажмите **«+ Добавить показатель СПУ»** (или **«+ Показатель»** на узле).  
2. Заполните как минимум:

| Поле | Значение |
|---|---|
| **Название *** | Понятное имя, как в отчёте |
| **Тип показателя *** | «Ручной ввод» / «Из Work Time» / «Расчётный» / «Из 1С (позже)» |
| **Основной департамент СПУ *** | Куда показатель «привязан» в дереве |

3. Рекомендуется сразу включить **«Показывать в План–факте»**, если показатель должен быть в отчёте.  
4. Нажмите **«Сохранить»**.

После сохранения показатель появляется в списке и в дереве выбранного департамента. История и идентификатор показателя при обычном редактировании **не создаются заново** — правите тот же показатель.

### 4.3. Полезные необязательные поля

| Поле / переключатель | На что влияет |
|---|---|
| **Дополнительно использовать в департаментах** | Показать тот же показатель ещё в других узлах (копия не создаётся — одно значение) |
| **Тип использования в СПУ** | «Итоговые данные» или «Ключевой показатель» (для классификации в «Настройка показателей») |
| **Блок** | Группировка ключевых показателей |
| **Ответственный за заполнение** / **за контроль** | Кто виден в «Ввод показателей» и в План–факте |
| **Тип результата** | Число, количество, деньги, процент, дни, часы — влияет на отображение |
| **Периодичность** | День / неделя / месяц |
| **Начало отчётной недели** | Например «Четверг–среда» |
| **Оценка динамики** | «Рост — хорошо» / «Снижение — хорошо» / «Не оценивать» — для колонки динамики в План–факте |
| **Способ расчёта** | Сумма / Среднее / Один источник / Формула |
| **Показывать расшифровку** | В План–факте показывать строки по источникам |
| **Порядок** | Число сортировки |
| **Статус** | Активен / Архив |

### 4.4. Переместить показатель и изменить порядок

- Сменить **«Основной департамент СПУ»** в карточке и сохранить.  
- Отметить дополнительные департаменты галочками.  
- В дереве структуры у показателя — кнопки **↑** / **↓** («Выше» / «Ниже»).  
- Либо изменить поле **«Порядок»** в карточке.

Отдельной кнопки «Переместить показатель» нет: перенос делается через поля департамента.

### 4.5. Редактировать без потери истории

1. Откройте показатель → **«Настроить»**.  
2. Измените нужные поля.  
3. **«Сохранить»**.

Программа сохраняет тот же показатель. Планы, факты и прошлые версии источников/формул не обнуляются только из‑за открытия карточки.  
Архивация (**«Архивировать»**) и мягкое удаление сохраняют историю — в интерфейсе есть соответствующие сообщения.

## 5. Чем отличаются понятия

| Понятие | Простыми словами |
|---|---|
| **Показатель СПУ** | Строка, которую вы контролируете в отчёте (название, департамент, план, факт) |
| **Источник** | Откуда берётся факт (метрика WorkTime, ручной ввод, другой показатель и т.п.) |
| **План** | Целевое значение на неделю; обычно задаётся в **«Планы СПУ»** |
| **Факт** | Фактическое значение за неделю (автоматически или вручную) |
| **Формула** | Правило расчёта факта и/или плана из других показателей и чисел |

## 6. Ручной ввод

### 6.1. Создать показатель с ручным фактом

1. **Структура СПУ** → **Показатели СПУ** → **«+ Добавить показатель СПУ»**.  
2. **Тип показателя** — **«Ручной ввод»**.  
3. Укажите название и основной департамент.  
4. Включите **«Показывать в План–факте»**.  
5. **Сохранить**.

### 6.2. Ввести факт за неделю

1. Меню **СПУ** → **Ввод показателей**.  
2. Выберите нужную неделю в панели периода (toolbar периода вверху).  
3. Выберите вкладку департамента.  
4. При необходимости фильтры: **Ответственный**, **Статус** («Не заполнено» / «Заполнено»), чипы **Все** / **Требуют заполнения** / **Заполнено**.  
5. В колонке **«Значение»** введите число для показателя.  
6. Сохраните изменения так, как предлагает экран (после ввода программа сохраняет данные при штатном сохранении раздела).  
   **Требуется проверка в интерфейсе:** точная кнопка/момент автосохранения ячейки на вашей сборке.

Результат: в **План–факт компании** за эту неделю в колонке **Факт** появится введённое число.

Автоматические показатели (из WorkTime / расчётные) в «Ввод показателей» обычно **не требуют** ручного заполнения — у них другой «Источник / статус».

## 7. Источники WorkTime и автоматический факт

### 7.1. Создать показатель «Из Work Time»

1. Откройте карточку показателя.  
2. **Тип показателя** — **«Из Work Time»**.  
3. **Способ расчёта** — чаще всего **«Сумма»** или **«Один источник»** (если источников несколько — «Сумма» / «Среднее»).  
4. В блоке источников нажмите **«+ Добавить источник»**.  
5. **Тип источника** — **«Метрика Work Time»**.  
6. В подборе метрики доступны фильтры:

| Фильтр | Смысл |
|---|---|
| **Раздел** | Все / Магазин Володарского / Территория |
| **Отдел** | Уточнение подразделения |
| **Рабочая группа** | Группа в метриках (если есть) |
| **Поиск** | Поиск по названию метрики |

Отдельного фильтра «Сотрудник» в этом подборе **нет**.

7. Выберите метрику из списка.  
8. Для нового выбора результат по умолчанию — **«Итого метрики — все участники»** (общий итог по участникам метрики).  
9. Укажите **«Неделя начала действия изменений»** (см. раздел про даты).  
10. **Сохранить**.

После сохранения программа применяет выбранные источники к выбранной неделе и к более поздним настройкам показателя (история прошлых недель не затирается незаметно).

### 7.2. Готовые автоматические источники (примеры из программы)

В списке метрик для СПУ можно встретить, в том числе:

- **Сумма продаж / выручка магазина (кассиры + КСО)**  
- **Количество чеков магазина (кассиры + КСО)**  
- **Количество покупателей магазина**  
- **Итог инвентаризации магазина**  
- **Итог инвентаризации склада**  
- **Деньги — итого ОПТ**  
- **Деньги — итого Розница/Склад**

Имена в коротком справочнике метрик могут быть короче; в подборе источника СПУ часто показываются расширенные подписи.

### 7.3. Несколько источников в одном показателе

1. **Способ расчёта** — **«Сумма»** (или **«Среднее»**).  
2. Добавьте несколько строк **«+ Добавить источник»**.  
3. Для каждой выберите свою метрику.  
4. При необходимости включите **«Показывать расшифровку»** — в План–факте будут видны составляющие.  
5. **Сохранить**.

Программа сама сложит (или усреднит) значения источников за неделю.

### 7.4. Как проверить, что источник работает

1. Убедитесь, что в исходном разделе WorkTime за дни этой недели данные уже есть (продажи, инвентаризация, Финконтроль и т.д.).  
2. Откройте **План–факт компании**, выберите нужную неделю.  
3. Найдите показатель: колонка **Факт** должна показать число.  
4. Если факт — прочерк **«—»**, а не ноль, данных за неделю нет или источник ещё не действует с выбранной даты (см. раздел 11 и 12).

Для формул дополнительно есть кнопка проверки (раздел 9).

## 8. Планы

План **не путать** с источником факта.

### 8.1. Основной способ: вкладка «Планы СПУ»

1. Меню **СПУ** → **Настройка показателей**.  
2. Вкладка **«Планы СПУ»**.  
3. Если периодов нет — нажмите **«+ Период»** и создайте **управленческий период**:

| Поле | Пример |
|---|---|
| **Название *** | «Ноябрь 2026» |
| **Дата начала *** | 30.10.2026 |
| **Дата окончания *** | 03.12.2026 |
| **Статус** | Активен |

Управленческий период **не обязан** совпадать с календарным месяцем. Внутри него программа считает отчётные недели СПУ (обычно чт→ср).

4. В списке показателей укажите значение плана и тип:

- **Накопительный** — сумма периода **делится равномерно** по отчётным неделям внутри периода.  
- **Целевое** — **одно и то же** значение копируется на каждую неделю периода **без деления**.

5. Нажмите сохранение у строки или **«Сохранить все планы»**.

Пример накопительного плана: период из 4 недель, план 400 000 ₽ → на каждую неделю попадёт по 100 000 ₽.  
Пример целевого: план 100 000 ₽ → на каждой неделе в колонке **План** будет 100 000 ₽.

### 8.2. План в карточке показателя

В карточке есть пояснение: основной план задаётся во вкладке **«Планы СПУ»**.  
Точечная правка недели **не заменяет** план управленческого периода. Пустое поле плана в карточке **не очищает** планы из «Планы СПУ».

### 8.3. План по формуле

Если тип показателя **«Расчётный»** или для WorkTime включён расчёт плана:

- включите **«Считать план по формуле»** или **«Рассчитывать план по формуле»**;  
- соберите **«Формулу плана»** (как в разделе 9);  
- сохраните с нужной **датой / неделей начала действия**.

Тогда план в отчёте считается автоматически и **не обязан** совпадать с ручным вводом в «Планы СПУ» для этой настройки.

## 9. Формулы СПУ (подробно)

Формулы доступны у **расчётных** показателей (и план-формула — также у WorkTime при включённом переключателе).

### 9.1. Две разные формулы

| Блок в карточке | Что считает |
|---|---|
| **Формула факта** | Значение в колонке **Факт** |
| **Формула плана** | Значение в колонке **План** (если включён расчёт плана по формуле) |

Включатели:

- **«Считать план по формуле»** (расчётный показатель);  
- **«Рассчитывать план по формуле»** (показатель «Из Work Time»).

### 9.2. Как собрать формулу

В блоке формулы доступны кнопки:

- **«+ Добавить элемент»** — выбрать другой показатель СПУ и тип значения;  
- **«+ Операция»** — знаки **+ − × ÷**;  
- **«+ Число»** — константа;  
- **«(»** и **«)»** — скобки.

Для элемента показателя выберите один из вариантов:

| Вариант в списке | Что берётся |
|---|---|
| **Факт СПУ — текущая неделя** | Факт другого показателя за ту же отчётную неделю, что смотрите |
| **Факт СПУ — предыдущая неделя** | Факт за прошлую отчётную неделю |
| **План СПУ — текущая неделя** | План другого показателя за текущую неделю |
| **План СПУ — предыдущая неделя** | План за прошлую неделю |

**Подтверждено программой:** в конструкторе есть текущая и предыдущая неделя.  
**Не реализовано в конструкторе:** «две недели назад», «три недели назад», календарный месяц, квартал, произвольный диапазон дат как операнд формулы.

### 9.3. Операции с числами — примеры

Допустим, в формуле участвуют константы и уже посчитанные значения операндов.

**Сложение.**  
Запись: `120 000 + 80 000`  
Результат: **200 000**

**Вычитание.**  
Запись: `200 000 − 50 000`  
Результат: **150 000**

**Умножение.**  
Запись: `1 000 × 12`  
Результат: **12 000**

**Деление.**  
Запись: `90 000 ÷ 3`  
Результат: **30 000**

**Скобки.**  
Запись: `(100 + 50) × 2`  
Результат: **300**  
Без скобок `100 + 50 × 2` даст **200** (сначала умножение, затем сложение).

**Константа.**  
Например, умножение доли на **100**, чтобы получить проценты для отображения:  
`(1 − ФактA ÷ ФактB) × 100`  
Если A = 80, B = 100: `(1 − 0,8) × 100` = **20**.

Отдельной кнопки «процент %» как операции **нет**. Для процентов обычно используют деление и умножение на 100, а в карточке показателя выбирают **тип результата «Процент»**.

### 9.4. Примеры с показателями

**Пример А. Сумма двух фактов текущей недели**  
Задача: «Выручка всего = ОПТ + Розница/Склад».  
Формула факта:

1. Элемент: показатель «Деньги ОПТ», **Факт СПУ — текущая неделя**  
2. Операция **+**  
3. Элемент: показатель «Деньги Розница/Склад», **Факт СПУ — текущая неделя**

Если ОПТ = 1 200 000, Розница/Склад = 800 000 → факт = **2 000 000**.

**Пример Б. Отклонение факта от плана**  
Формула факта (или отдельный показатель «Отклонение»):

1. Факт показателя «Продажи», текущая неделя  
2. **−**  
3. План того же (или другого) показателя, текущая неделя  

Если факт 110, план 100 → результат **10**.  
Если факт 90, план 100 → результат **−10**.

**Пример В. Выполнение в процентах**  
`( Факт ÷ План ) × 100`  
Факт 90, план 100 → **90**.  
При типе результата «Процент» в отчёте это отобразится как процентное значение (программа **не умножает ещё раз на 100** при показе единицы «процент»).

**Пример Г. Сравнение с прошлой неделей**  
`Факт текущей − Факт предыдущей`  
Текущая неделя 150, предыдущая 120 → **30**.

### 9.5. Пустые данные, ноль, деление на ноль

| Ситуация | Что увидите |
|---|---|
| Нет данных у операнда | Итог формулы пустой → в отчёте часто **«—»** / «Нет данных» |
| В операнде явное значение **0** | Это ноль, он участвует в расчёте |
| Деление на ноль | Результат считается отсутствующим (**не число**), в проверке — «Нет данных» |
| Показатель ссылается сам на себя как «факт текущей недели» | Не допускается, результат пустой |

Запомните: **«—» ≠ 0**. Прочерк значит «нет данных», ноль значит «данные есть, значение ноль».

### 9.6. Проверить формулу до сохранения результата отчёта

В карточке:

1. Выберите неделю в поле **«Проверить формулу за период (чт–ср)»**.  
2. Нажмите **«Проверить формулу факта»** или **«Проверить формулу плана»** (есть также проверка факта текущего периода UI).  
3. Посмотрите таблицу операндов: у каждого — число или **«нет данных»**, внизу — итог.

Проверка считает **черновик** формулы на экране и **не заменяет** уже сохранённую историю сама по себе. После успешной проверки нажмите **«Сохранить»** в карточке показателя.

### 9.7. С какой даты действует формула

Укажите **«Дата начала действия изменений»** (для расчётных) или соответствующую неделю начала для связанных настроек.  
Прошлые недели остаются на прежней версии формулы. Новая формула действует с указанной даты на текущую и (в зависимости от выбора при сохранении) на более поздние настройки.

## 10. Даты и история — простыми словами

| Что | Смысл для финансиста |
|---|---|
| **Отчётная неделя** | Неделя чт–ср, которую смотрите в План–факте или во «Ввод показателей» |
| **Неделя / дата начала действия изменений** | С какого момента действует **новый** источник или **новая** формула |
| **Предыдущая неделя в формуле** | Откуда формула берёт данные (сдвиг на одну отчётную неделю назад), это **не** то же самое, что дата начала действия |
| **Управленческий период** | Диапазон дат для задания планов в «Планы СПУ» |

**Пример.**  
До 5 ноября источник был «Чеки». С 5 ноября выбрали «Сумма продаж».  
Неделя 29.10–04.11 всё ещё считает чеки.  
Неделя 05.11–11.11 и дальше — сумму продаж.

Открытие карточки **само по себе** историю версий не меняет — меняет **сохранение** с новой датой начала.

## 11. План–факт компании

### 11.1. Открыть отчёт

1. Меню **СПУ** → **План–факт компании**.  
2. Заголовок: **«НЕДЕЛЬНЫЙ ПЛАН ОРГАНИЗАЦИИ»**.

### 11.2. Выбрать недели и фильтры

| Элемент | Назначение |
|---|---|
| **Неделя 1 (базовая)** | Первая сравниваемая неделя |
| **Неделя 2 (сравниваемая)** | Вторая неделя |
| **Ответственный** | Фильтр по ответственному |
| **Департамент** | Фильтр по узлу структуры |

Подсказка на экране: в отчёт попадают только показатели с галочкой **«Показывать в План–факте»**. Дерево берётся из **«Структура СПУ»**.

### 11.3. Колонки

Для каждой недели:

- **План**  
- **Факт**  
- **Выполнение, %**

Сравнение:

- **Изм., п.п.**  
- **Динамика**  
- **Статус** (например «Улучшение», «Ухудшение», «Нет данных»)

### 11.4. Откуда значения

- **План** — из «Планы СПУ» (разложенный на недели) или из формулы плана.  
- **Факт** — из ручного ввода, WorkTime/встроенных источников или формулы факта.  
- **%** — отношение факта к плану (когда оба числа есть).

### 11.5. Почему факт пустой и как отличить ноль

1. Нет галочки **«Показывать в План–факте»** — строки вообще нет.  
2. Факт **«—»** — данных нет (метрика пустая, источник ещё не действует, формула получила пустой операнд).  
3. Факт **0** — данные есть, сумма за неделю ноль.  
4. Проверьте, что исходные данные в WorkTime/Финконтроле за дни этой недели заполнены.  
5. Для формулы — **«Проверить формулу факта»** на ту же неделю.

### 11.6. Проверить прошлую неделю

Выберите нужную неделю в **Неделя 1** / **Неделя 2**.  
Сравните план и факт двух недель и колонку **Динамика**.

## 12. Практические сценарии

### Пример 1. Ручной план и факт

**Задача:** контролировать «Прочие доходы» вручную.

1. Создайте департамент (если нет).  
2. Создайте показатель, тип **«Ручной ввод»**, включите План–факт.  
3. В **Планы СПУ** задайте план на период (накопительный или целевой).  
4. Во **Ввод показателей** введите факт за неделю.  
5. В **План–факт** проверьте План, Факт и %.

Типичная ошибка: забыли галочку План–факт — строки в отчёте нет.

### Пример 2. Автоматический факт из WorkTime

**Задача:** факт «Чеки магазина» из метрик.

1. Показатель тип **«Из Work Time»**.  
2. Источник — метрика чеков (встроенная подпись про кассиров + КСО).  
3. Результат — **«Итого метрики — все участники»**.  
4. Неделя начала действия — четверг нужной недели.  
5. Сохранить → открыть План–факт.

Типичная ошибка: в метриках касс за неделю пусто — в ПФ будет «—», а не ошибка сохранения.

### Пример 3. Деньги Финконтроля в СПУ

**Задача:** показать «Деньги — итого ОПТ» и «Деньги — итого Розница/Склад».

1. Два показателя (или один суммирующий — см. пример 5).  
2. Тип **«Из Work Time»**, источник — соответствующая денежная метрика из списка.  
3. Сохранить с даты начала.  
4. Убедиться, что в Финконтроле за дни недели есть поступления по Территории.  
5. Проверить План–факт.

Типичная ошибка: источник выбран, но за неделю в Финконтроле ещё нет строк — факт пустой.

### Пример 4. Несколько источников

**Задача:** один показатель = сумма двух метрик.

1. Способ расчёта **«Сумма»**.  
2. Два источника → две метрики.  
3. При необходимости **«Показывать расшифровку»**.  
4. План–факт: общий факт и строки расшифровки.

### Пример 5. Формула из двух показателей

См. раздел 9.4, пример А.  
Сначала создайте и проверьте два исходных показателя, потом расчётный.

### Пример 6. Отклонение плана от факта

См. раздел 9.4, пример Б.  
Создайте отдельный расчётный показатель «Отклонение», чтобы не путать с исходными продажами.

### Пример 7. Предыдущая неделя в формуле

См. раздел 9.4, пример Г.  
В конструкторе выберите **«Факт СПУ — предыдущая неделя»**.  
Других сдвигов («−2 недели» и т.п.) в списке **нет**.

### Пример 8. Смена источника с даты

1. Откройте показатель → **Источники** / **Настроить**.  
2. Выберите новый источник.  
3. Укажите **«Неделя начала действия изменений»** (будущий или текущий четверг).  
4. Сохраните.

Прошлые недели остаются на старом источнике. Проверьте План–факт за неделю **до** и **после** даты.

## 13. Порядок первоначальной настройки (чеклист финансиста)

1. **Структура СПУ** → создать дерево департаментов.  
2. **Показатели СПУ** → создать показатели, разместить, включить **«Показывать в План–факте»**.  
3. Для автофактов — источники WorkTime / встроенные метрики; для ручных — тип «Ручной ввод».  
4. Для расчётных — формулы факта/плана, проверка за неделю, сохранение с даты.  
5. **Настройка показателей → Планы СПУ** → период и планы.  
6. **Ввод показателей** — заполнить ручные факты текущей недели.  
7. **План–факт компании** — две недели, сверка плана/факта/%.  
8. Если факт «—» — проверить исходные данные и дату начала действия, затем формулу (если есть).

## 14. Что пока нельзя сделать в программе

| Ожидание | Статус |
|---|---|
| Формула «как две / три недели назад» | Не реализовано в конструкторе (есть только текущая и предыдущая) |
| Месяц / квартал / произвольный диапазон как операнд формулы | Не реализовано |
| Загрузка планов из Excel | Не реализовано |
| Интеграция с Google Таблицами | Не реализовано |
| Тип показателя «Из 1С» | В интерфейсе помечен как «позже», полноценно не используется |
| Фильтр «сотрудник» в подборе метрики источника СПУ | В подборе нет |

Если функция нужна для работы, но её нет в списке кнопок — это ограничение программы, а не ошибка вашей настройки.

## 15. Краткая памятка проверки

Перед тем как считать отчёт готовым:

1. Показатель в нужном департаменте и **активен**.  
2. Галочка **«Показывать в План–факте»**.  
3. План задан в **«Планы СПУ»** или формулой плана.  
4. Факт: ручной ввод **или** рабочий источник **или** формула.  
5. Дата/неделя начала действия покрывает проверяемую неделю.  
6. В План–факте число, а не «—» (либо осознанный ноль).  
7. Для формул — «Проверить формулу…» за ту же неделю даёт ожидаемые числа.
